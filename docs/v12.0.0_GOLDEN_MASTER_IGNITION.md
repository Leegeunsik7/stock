## 2. 물리 이중 키 · Stage-1 소액 카나리 점화 수순

> ⚠️ **본 수순은 물리 키 접점을 가진 운영자만 수행한다. 에이전트/자동화는 물리 키를 무장하지 않는다.**

`liveArmed:false`는 **소프트웨어 단독으로 절대 해제되지 않는다.** 실 발주 인가(`CanaryHealthSentinel.TryAuthorize > 0`)는 물리 이중 키가 **둘 다** 접점 연결됐을 때만 성립한다.

1. **콜드 부팅 확인** — 앱 기동 직후 `CanaryHealthSentinel.IsArmed == false`, `IsKilled == false`. 부팅 무결성 센티널 로그(`[GoldenMaster]`)에 결함 없음.
2. **밸브 키 접점** (`ValveWired = true`) — 1차 물리 키 삽입/회전.
3. **라이브 무장 키 접점** (`LiveArmingWired = true`) — 2차 물리 키 삽입/회전.
4. **소액 무장** — `Arm(capRaw, valveWired: true, liveArmingWired: true)` 호출. **한 키라도 결여 시 `Arm`은 실패하고 disarmed 유지**(fail-closed). Stage-1 cap은 총자산의 **0.1%**(`총자산 × 0.001`)로 봉인.
5. **1건 소액 발주 실증** — `TryAuthorize(notional)`가 비영(非零) 인가 토큰을 1회 반환하는지 확인. 누적이 cap을 1원이라도 초과하면 **즉시 Kill**(폭발 반경 차단).
6. **단계 승격** — `StepUpTierGovernor`로 0.1% → 1% → 5% → 25% → 100% 단조 승격(각 단계 물리 재확인). 임의 단계에서 롤백 시 `InstantRollbackPurger`가 권한 버퍼를 0x00 소거.

**재무장 규약**: 킬스위치 격발 후 재무장은 `TryRearm(valveWired: true, liveArmingWired: true)` — **물리 이중 키만**. 소프트웨어 명령 단독으로는 복구 불가(sticky).

## 3. 킬스위치 주입 · 0ms 토큰 소거 · 메모리 중독 재검증

하드웨어 킬스위치(USB/COM 버튼·NamedPipe·MMF 워치독)는 다음을 **원자적(<50ms, 사실상 동기)** 으로 수행한다:

1. **전역 Disarm** — `HardwareKillSwitchBridge.Signal(reason)` → sticky `_killed`. 이후 어떤 소프트웨어 명령으로도 `liveArmed` 복구 불가.
2. **CancellationToken 취소** — 진행 중 모든 퀀트/발주 토큰 취소(API 통신·발주 인가 0).
3. **0ms 토큰 소거(0x00)** — `CanaryHealthSentinel.Kill` → `_armed=0` + 발주 토큰 버퍼 `CryptographicOperations.ZeroMemory`(0x00) + sticky 락아웃.
4. **API Secret 메모리 중독** — `VolatileMemoryPurger.PurgeAll`(등록 버퍼 0x00) + `PoisonedSecretBuffer.PurgeAndPoison`(소거 + **중독 표식**).

**재검증 체크리스트** (스테이징 주입 시):
- [ ] `bridge.IsKilled == true` · `bridge.Token.IsCancellationRequested == true`
- [ ] `canary.IsKilled == true` · `TryAuthorize(1)`가 **2,000회 연속 0** 반환
- [ ] `purger.AllZero == true` — 등록 Secret 버퍼 전 바이트 0x00
- [ ] `PoisonedSecretBuffer.ReadByte/CopyTo/AsSpan`가 **`ObjectDisposedException`** — 소거 후 재참조(뒤늦은 async API 키 재사용) 즉시 차단
- [ ] 다중 전송로 동시 주입 시 `Killed` 이벤트 **정확히 1회**(`LockFreeSignalDemuxer` 포화마스크 경합 승자 결정론)

> 회귀 검증: `Phase95HardwareKillSwitchTests`, `HardwareKillSwitchStressTests`(100k+ ticks/sec·풀기아·4전송로), `Phase96SignalDemuxerTests`, `StagingFieldAuditSimulationTests`(24h 이중 브로커).

## 4. 부팅 무결성 센티널 (Golden Master Boot-Time Integrity Sentinel)

`GoldenMasterBootSentinel`은 부팅 시 **리플렉션 정적 산술 스캔**으로 5대 무결성 축을 검사하고, **단 1개라도 결함이면 fail-closed**(`AllPassed=false`)로 판정한다. 판정 커널 `Evaluate`는 unmanaged 체크 스팬을 stackalloc으로 순회 → **δ=0(힙 0)·결정론**.

| # | 축 (`GmCheckId`) | 통과 조건 |
|---|---|---|
| ① | `RclZeroEngineRef` | `MS2E.UI.Portable`이 호스트/엔진 어셈블리를 역참조하지 않음(0 Concrete Ref 물증) |
| ② | `HostCoupledWithinRatchet` | 호스트 결합 UI ≤ PureShell 래칫(40) |
| ③ | `LiveArmedFalse` | 부팅 시 카나리 미무장 |
| ④ | `DualKeyAbsent` | 물리 이중 키 미연결(안전 기본) |
| ⑤ | `VaultSealed` | API 금고 DPAPI 봉인(평문 시크릿 0) |

**Strict 골든마스터 빌드**: 위 스캔이 `!AllPassed`면 **앱 부팅을 거부**(fail-closed). 개발/CI 빌드는 로그(`[GoldenMaster]`)만 남기고 진행한다. `VaultSealed`는 strict 빌드에서 실제 DPAPI 봉인 검사(`ApiKeyVault`)로 대체한다.

> 회귀 검증: `Phase98GoldenMasterTests`(fail-closed 판정·δ=0·실 어셈블리 스캔).

## 5. 데이터 마샬링 방어 (Zero-Alloc Row Stream Mapper)

`ValidateHub`(Calibrator/Twin) 등 대용량 검증/예측 조회의 **DataRow 힙 가비지(LOH 타격)** 를 제거하기 위해, 원시 SQL은 `IValidateRepositoryPort` **단일 초크포인트**로 격리되고, `LocalDatabase.QueryProject`가 `ZeroAllocRowStreamMapper`로 **SqliteDataReader → 레코드 직접 투사**(DataTable/DataRow 무물성화)를 수행한다.

- `Project<T>(cursor, Span<T> dest, proj) where T:unmanaged` — 숫자 스트림 O(1) **δ=0** 투사.
- `MapAll<T>(cursor, proj)` — 문자열 포함 DTO도 행당 DataRow 물성화 0.

> 회귀 검증: `Phase98GoldenMasterTests`(Project δ=0·MapAll 무 DataRow).
